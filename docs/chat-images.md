# Chat attachments and downloads

Incoming image attachments render directly beneath message content, independently of rich embeds. Clicking an image opens a full-window egui modal with a dark backdrop, filename, available description, dimensions and file size. Close, Escape or clicking outside the modal dismisses it. Download opens a native Save dialog for the original file. Non-image attachments offer Download beside their existing browser-open action, with filename and byte size visible. Progress and Cancel download appear in the channel header and image viewer; controls survive scrolling, closing the viewer and channel navigation. The viewer expands within the application window and does not switch the operating system into fullscreen mode. The displayed preview remains a bounded static image, not a full-resolution zoom/pan viewer. Single-file uploads are implemented separately; animated playback remains unimplemented.

The wire shape is based on [Discord's attachment object](https://docs.discord.com/developers/resources/message#attachment-object): IDs, filename, description, content type, size, original/proxy URLs and nullable dimensions. History, message creation and partial updates retain these attributes. Absent attachment patches preserve existing images; null/empty arrays remove them. Attachment changes invalidate layout and old spoiler-reveal consent; deletes, navigation and eviction close a now-unavailable viewer. The SUPPRESS_EMBEDS message flag does not hide attachments.

The documented IS_SPOILER attachment flag (bit 3) and legacy SPOILER_ filename prefix require explicit reveal before any attachment preview request. As a conservative compatibility measure, the [public discord.py-self sensitive flags](https://github.com/dolfies/discord.py-self/blob/master/discord/flags.py#L3237-L3254) (bits 4, 6 and 7) also require reveal. These additional flags are unofficial implementation evidence. As with existing message spoilers, the whole message body/media is concealed until revealed, and changes revoke that consent. Images do not bypass existing text/embed spoiler concealment.

PNG, JPEG, WebP, GIF and AVIF media types select the static preview path; a recognized filename extension is used only when the content type is absent. Other files show an unavailable-preview label and are never decoded or executed. The existing credential-free Discord media worker converts service images to a bounded static PNG response. Conversion is unofficial and live-unverified; animated images display a still preview. Arbitrary external origins, redirects, credentials and unbounded decoders remain disallowed. See [the shared image-cache policy](icons.md) for origin, body, dimension, queue and memory limits. Failed or unsupported conversion leaves a visible placeholder. Download is a deliberate action independent of preview conversion or MIME type; opening the file externally remains a separate action.

Each message admits at most 10 attachments and 64 KiB of attachment metadata. Filename/description/type/URL lengths are bounded during normalization. Both wire and cache arrays reject excess items during parsing; metadata counts toward the existing 4 MiB active window and 1 MiB pending-patch budget. SQLite schema 6 retains the bounded attachment JSON introduced in schema 5 (256 KiB/record), preserves prior messages/drafts/embeds, and adds bounded mentioned-user metadata. Serialized attachment and mention bytes count toward eviction. Signed image URLs are unencrypted local metadata; cached image files share account isolation and logout/clear-cache cleanup. The existing 16 MiB/64-texture and 1 GiB/4096-file disk allowances are unchanged. No new decoder dependency or bitmap asset is bundled; native destination selection uses rfd 0.17.2.

## Explicit original downloads

Saving starts only after the user chooses a destination in the native dialog. Cocoa/Windows dialogs and the Linux desktop FileChooser portal own this interaction; the macOS dialog future is constructed on the UI thread. The app retains one dialog/download slot until it finishes. Cancel during destination selection prevents the transfer but the native dialog still needs to be dismissed. Downloads are disabled for all synthetic demo attachments. Suggested names preserve ordinary extensions while removing unsafe path/control characters; an empty result becomes the extensionless `attachment`.

The separate credential-free download client accepts only HTTPS `cdn.discordapp.com/attachments/{channel}/{attachment}/{filename}` originals with the selected attachment ID and permitted signed `ex`/`is`/`hm` query parameters. It does not use proxies, follow redirects, send account credentials, or write URLs to status messages/logs. Any attachment type is eligible with a known size of 1 byte through 100 MiB; this is a local save limit, not an account entitlement. The completed response must exactly match that size. Signed URL rejection or a changed size requires reloading the conversation. Media-proxy transformations are not saved in place of the original. Discord's [attachment fields](https://docs.discord.com/developers/resources/message#attachment-object) and [signed CDN URL reference](https://docs.discord.com/developers/reference#signed-attachment-cdn-urls) were rechecked September 10, 2026; live normal-user delivery remains unverified.

One dedicated worker streams the response, writes blocks of at most 32 KiB and coalesces progress to at most ten updates per second. Connection/read/whole-request timeouts are 15/30/300 seconds. It neither decodes the downloaded file nor holds a complete original image in memory. A randomized hidden sibling `.serein-*.partial` file is created exclusively, flushed, then published. Native Save confirmation authorizes replacing the selected existing regular file only after the complete transfer; an incomplete or cancelled response cannot truncate it. New destinations use an atomic hard link and temporary-file removal, preserving a file that appears meanwhile. Filesystems without hard-link support fail visibly rather than using a destructive fallback. Symlink and directory destinations are rejected.

Cancellation is checked during transfer and again after flushing, immediately before publication. Logout and application teardown cancel the worker; normal window close waits for it to finish. Closing the image viewer alone does not cancel a requested download. Cleanup failures appear in status. Forced termination or filesystem failures can leave a partial sibling; cleanup is not a crash-proof guarantee. User-selected downloads are outside the application cache and are not removed by cache clearing or logout.

Offline tests cover image-only messages, nullable dimensions, spoiler flags, metadata limits, partial updates/deletion and late-history reconciliation, schema migration/reopen/account isolation, hidden media requests and attachment-only reveal/viewer invalidation. A synthetic local HTTP test verifies original bytes, overflow/truncation, cancellation including a stalled response, preservation of existing files, explicit replacement, concurrent destination creation and cleanup-error reporting. Filename sanitization is tested separately. These tests use temporary synthetic files and no Discord traffic. Native Save dialog interaction, physical filesystem/platform differences, live account delivery and expired/signed URL recovery remain unverified; offline checks do not satisfy the owner-controlled Discord exchange milestone.

The September 10 general-file continuation extends that worker test with PDF/octet-stream/absent-MIME admission, zero/oversized rejection, exact arbitrary binary bytes (including NUL and invalid UTF-8), and ordinary extension preservation. Synthetic egui tests exercise deliberate keyboard Download, disabled demo/active/pending requests, no automatic preview/external commands, Cancel download and preservation of controls across navigation. Generated demo message 500 now includes a text-file attachment alongside its image; it has no actual downloadable content, and its Download button is disabled. No new native Save interaction or live CDN test was performed.
