# Native message embeds

Implemented September 10, 2026. Cards render titles, descriptions with the existing bounded Markdown subset, authors/providers, inline or full-width fields, accent color, footer/timestamp, thumbnails and static images. Narrow layouts stack fields and thumbnails. Oversized cards scroll within a 640-pixel content area. Video/gifv cards expose an explicit browser link; no media player, HTML renderer or automatic animation is added. Unknown embed types retain available attributes plus an unsupported-content label.

[Discord's message reference](https://docs.discord.com/developers/resources/message#embed-object) documents the embed attributes and message suppression flag. The [Gateway message update](https://docs.discord.com/developers/events/gateway-events#message-update) uses message fields. These shapes are protocol evidence; normal-user acceptance remains unofficial and live-unverified. The DTO retains embeds from history, message creation and partial updates. An absent embed patch preserves existing cards; null or an empty list clears them. Suppression hides cards. Embed-only updates invalidate layout and revealed spoiler content; mutations observed during a history request win over its older response.

Message text or visible embed text containing spoiler delimiters conceals the whole message body and all its embeds until explicit reveal. Reveal consent compares the exact content and embed attributes, is pruned with the retained timeline, and resets when those attributes change. Markdown links and bare HTTP(S) URLs in descriptions and field values are clickable inline, retain surrounding formatting, expose their destination on hover, and support keyboard activation. Inline code, code blocks and unsafe destinations remain inert. Rendering alone never opens a link. All external destinations use the existing scheme/origin validation and confirmation dialog, and images use only the credential-free service-media worker described in [icons.md](icons.md).

Both wire and cache parsing admit at most 10 embeds and 25 fields per embed before allocating further entries. Text attributes have service-shaped character limits; retained embed metadata additionally has a shared 64 KiB per-message estimate. Limited presentation is marked visibly. Those bytes participate in timeline, event and pending-patch budgets; the timeline remains 500 messages / 4 MiB, pending mutation content 1 MiB. FormatCache shares its existing 64-entry / 1 MiB ceiling across message and embed sections. Image geometry is reserved from metadata, and layout fingerprints include embeds and suppression.

SQLite schema 4 preserves existing history/drafts and adds typed embed JSON plus suppression. Serialized embed JSON is capped at 256 KiB per record; bounded parsing and the retained-window limit apply again on hydration. SQL eviction counts serialized bytes. Image URLs, including service-signed query strings, are part of the unencrypted local message cache; image filenames contain only a digest. Clear cache/logout use the existing account cleanup policy. No separate database or service is introduced.

Offline checks cover structured decoding, over-limit input, absent/null/empty updates, suppression, late-history reconciliation, actual temporary SQLite migration/reopen and account isolation, UI spoiler hiding/reveal invalidation, safe external links, and synthetic image rendering. The demo contains a clearly labeled native embed and generated landscape without network access. Live Discord delivery, image proxy conversion acceptance and Windows/Linux presentation are not claimed tested.
